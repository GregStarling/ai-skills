# Ordinary dispatch and evidence coverage

Updated 2026-09-11. Delegate now separates ordinary host delegation from evidence-required routing. Repository language and size do not restrict ordinary dispatch; the bounded assignment, tool permissions, risk, available worker controls and verification determine whether it can proceed.

## Ordinary host dispatch

The helper's `dispatch` command uses two coordinator-supplied host slots: economy for location/source analysis and low-risk precise edits; standard for reproduction, features, fixes, UI, settled plans and medium-risk edits. These are declared starting heuristics, not measured savings or capability qualification. Missing slots, unsettled diagnosis/plans, unbounded work, high/critical risk and required reviewer gaps stop dispatch explicitly. It never selects a model from a guessed roster or reads the evidence pack.

Large-repository work follows locate, trace, change and integrate. A search can start before the owning package is known. Read scope follows relevant dependencies; write scope stays explicit. Cross-package work is divided at settled contracts, not file-count boundaries. Focused iteration checks are followed by affected consumer/integration and repository-required gates. Direct execution remains valid at any size when the whole delegated path is unlikely to save allowance.

A single outcome observation captures investigation or implementation acceptance, checks, repairs and optional observed usage. Recent same-project/assignment/model observations surface failure/repair history across guidance edits and differing free-text labels. Repository identity is derived from the working directory and shared by Git worktrees; scope labels are optional annotations, not matching keys. They do not promote models or establish economic preferences. Missing complete usage does not prevent failure feedback.
