# Human governance policy

`constitution.json` is policy v4. It separates capability qualification from economic selection for subscription-first execution. `constitution-v3.json` preserves the exact previous policy bytes; `simulation-v1.json` preserves the policy used by synthetic binding examples. Old versions retain their original cost qualification rules. Model IDs remain registry data, never constitution constants.

Capability qualification uses exact task, role, risk, constraint, cohort and versioned evaluation evidence, minimum sample size, accepted-task rate, failure ceilings, latency, freshness, tools and runtime treatment identity. Missing dollars do not prevent v4 capability qualification. Production requests must identify `claude_code`, `codex` or `api`; missing runtime environment yields HOLD and a different environment rejects. API capability evidence does not silently establish subscription-host capability. Frontier verification requirements are unchanged.

V4 economics live in `SelectionInput.economics`, separate from capability observations. `economic_evidence.v1` references current official pricing sources, task-specific API observations, every attributable attempt and captured provider usage bytes. Each attempt binds an exact candidate identity, runtime receipt and original usage source. The governor re-parses official price documents with the existing discovery parser, verifies hashes, matches exact snapshot/effort and task stratum, and includes failed/review/rework attempts in API-equivalent cost per accepted task. The metric is a normalized relative API-cost proxy, **not the user's subscription bill**.

Economic ordering compares measured task economics when all eligible peers have them. Otherwise it uses comparable non-crossing official input/output prices; crossing, incomplete or unknown prices require a complete explicit `maintainer_order`. A measured value is not proof that it beats an unknown value. Capability and evidence precedence remain ahead of economics. An optional `eligibleCandidateIds` list restricts routes without dropping other candidates needed for attributable economic evidence; this restriction is part of decision identity.

The policy's API-equivalent ceiling filters measured economics during selection; it never changes capability qualification. Unknown economics may use the declared fallback order under the policy default. An explicit request/constraint dollar ceiling requires measured task economics before selecting a candidate. Incumbents that fail capability and incumbents that fail economic eligibility have separate diagnostic rule IDs. Automatic promotion still needs paired quality evidence and measured same-task API-equivalent economics; list-price proxies alone cannot prove a measured improvement.

Supported measured usage categories are disjoint. OpenAI ordinary input subtracts cached and cache-write subdivisions from total input; output already includes reasoning. Anthropic input excludes cached reads/writes. Zero-valued TTL metadata is accepted, but positive TTL writes require category rates the current overview parser does not expose. Unknown token categories, provider-hosted tool fees, or unresolved context/service-tier/geography pricing modifiers remain unknown; no multipliers, average token mixes, or overlapping reasoning charges are invented. Price source expiry is a declared 30-day proposal, not evidence that published rates never change.

Decisions hash economic inputs and recomputed results as well as observations. Binding validation re-derives pricing, ordering, capability and current eligibility, so changed economic authority invalidates a binding. Declared numeric policy values remain engineering proposals rather than measured model-performance claims.

Run `node dist/cli/index.js validate-policy policy/constitution.json` after building. Synthetic fixtures cannot grant production authority.
