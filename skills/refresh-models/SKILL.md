name: refresh-models
description: Maintain the delegate skill's portable routing pack using model discovery, versioned evaluation evidence and governor qualification. Use when a maintainer requests a routing refresh or asks to evaluate new models for delegate.
---

This is maintainer tooling. Consumers of the complete delegate folder never need the governor, its dependencies or this refresh workflow.

In the authorized ai-skills checkout, read `docs/routing-pack-maintenance.md`. Identify the current human policy, pack, task scopes, available evaluation sources and refresh trigger. Use existing discovery, evaluation and refresh commands to capture immutable official metadata and actual task/review outcomes. A public benchmark or advertised price does not itself qualify a task route. Record model × effort, material serving controls, failed attempts, review/rework and unknown costs without inventing telemetry.

Every refresh must identify each provider's current generally available frontier from fetched official documentation and update `data/routing/frontier-targets.json` with the exact model, source date and source digest. Probe those targets through the actual authenticated hosts with `node scripts/probe-frontiers.mjs` after building. The persisted report distinguishes unavailable from unknown, records host versions and errors, and does not infer native Agent availability from CLI success or catalog omission. When a model runs, evaluate and independently review its actual diagnostic/task output; record passed/failed with the review digest before publication. A successful greeting is insufficient. If it cannot run, preserve the specific reason and retain the next eligible evidenced frontier. Do not silently replace requested models or update global host software as part of a routing refresh.

Evaluate only within the user's authorized budget and available authentication. Reuse immutable evaluation IDs to avoid repeated spend. Preserve paired promotion rules and explicit HOLD results. Do not loosen qualification or hardcode illustrative model ladders to fill an empty pack.

Compile worker and frontier-reviewer strata with `compile-routing-pack`. Qualified treatments use the full governor envelope. Explicitly provisional treatments use the smaller host-smoke evidence contract; missing full qualification is distinct from an actual capability failure. Preserve requested versus observed controls and disclose price-ranking limits. An eligible qualified treatment wins over provisional alternatives. Inspect scope, ordering, effort, evidence references, controls and independent expiry. Reject synthetic authority, stale evidence and unsupported controls.

Feed matching installed acceptance records into provisional evidence by class, host, treatment and role. Preserve assisted UI recovery and browser evidence, failed attempts and original dates. Untested classes or candidates remain explicit smoke extrapolation. Project/swarm acceptance does not create a whole-project worker route. Diagnose hard bugs and settle complex-work architecture at the frontier before delegating implementation.

Within provisional ladders, matching installed acceptance outranks smoke extrapolation; apply economics only within the same evidence level. Archive real local receipts with `receipt-ingest`, then use `receipt-assess` with independent native task, attempt and review evidence. Read `docs/production-receipts.md`. Feed the returned `evaluationLedgers` references to the existing refresh/qualification/paired-selection flow. Include failures and unknown costs; do not relabel benchmark runs as production usage or promote unassessed receipts. Reassess after policy changes. Client attestation and governed task scopes remain prerequisites for qualification.

Policy v4 separates capability from economic selection; read `docs/v4-economics.md`. Missing billed USD cannot block capability. Keep actual `claude_code`/`codex` capability observations separate from API economic observations. Price exact treatments using independently captured API token categories and current official rates; never rank by raw token count or treat API success as host qualification. Measured comparable API-equivalent task costs precede comparable API-price proxies, then explicit maintainer order; none is a subscription bill. Preserve economic ceilings and measured paired-promotion requirements. Compile `routing_pack.v3` with shared treatment metadata and reinstall the complete folder; older packs/assessments are not silently reinterpreted.

Policy v5 retains those economics and adds validator-derived native identity assurance; read `docs/v5-identity-assurance.md`. Resolve preserved request/configuration, process, version and trace bytes. Never accept an agent-written assurance label or upgrade historical records without raw evidence. Preserve configured versus runtime-attested model/effort and unknown provider fallback behavior. Contradictory runtime identity rejects the treatment; missing stronger telemetry alone need not block low/medium work when exact configuration and all existing capability/review requirements are established. Probe availability and diagnostic success do not establish reviewer or coordinator qualification.

Stage the result first. Publish the exact reviewed pack into `skills/delegate/routing-pack.json` through the maintainer's normal authorized Git workflow; do not activate unrelated native bindings or modify consumer settings. An update to this repository is not automatically installed in another user's host. Report changed routes, retained incumbents, missing evidence and actual checks.

Validate publication timestamps with the current clock. Pack lifetime is separate from binding lifetime; refresh does not reset source/observation dates. Treat local `delegate_receipt.v1` files as observations to assess and import with provenance, never automatic promotion. `full_project` remains a decomposition mode; assess its required workstreams instead of adding a whole-project worker route.
