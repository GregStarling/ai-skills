# Local learning and session advice

The coordinator calls the packaged helper at task start, delivery, and useful milestones. Workers do not run it. It uses an existing Node runtime and built-ins; never install a runtime for learning. If unavailable, continue the task using baseline routing and mention the limitation briefly. No daemon, extra model runs, unrelated-chat monitoring, uploads, or edits to shared routing are involved.

Run `node <skill-folder>/scripts/local-learning.mjs <command> <input.json>`. Use absolute input and evidence paths. Commands return JSON; `unavailable` is a learning failure, not a task failure. Keep input files in local task artifacts, never in the installed folder. The helper stores personal state in `$XDG_STATE_HOME/delegate` or `~/.local/state/delegate`. `DELEGATE_STATE_HOME` is an explicit override for isolated evaluation. Git worktrees share project identity; hosts and non-Git projects remain isolated. Replacing the skill folder preserves state.

## Start and advice

Call `start` with `cwd`, `host` (`codex` or `claude`), `host_version` (actual version, or `unknown`), `session_id`, `task_class`, `risk`, and a short stable `scope` describing comparable work. `research_kind` is null, `supplied_sources`, or `live_web`. Optional fields: `task_id`, `run_id`, `baseline_digest`, `origin` (default `production_usage`, use `qualification_evaluation` for trials), and `parent_run_id` for an acknowledged fresh-session handoff. Reuse returned task/run IDs for repairs. A new session gets a new run ID linked to the prior completed run, with the same task ID/scope/origin.

Call `advise` with `cwd`, `host`, and `run_id`. For a delegated comparison also supply the actual `stratum_digest` and `pack_path`. The helper checks current pack freshness internally; a direct coordinator does not need to read the pack merely to collect a record. Advice returns `modePreference` and optional `localPreferences`; no advice means baseline. Apply mode advice only when it fits the present task and explicit instructions. Pass `localPreferences` unchanged into the maintainer resolver when used. Native coordinators apply the same boundaries: only reorder available provisional workers within the baseline worker's task-evidence level, retain qualified incumbents, and keep the exact eligible baseline reviewer. Recheck host capabilities, identity, effort, expiry, independence and task scope. Never use local preferences to invent a route.

Positive preferences need at least five distinct evidence-supported tasks per compared option in 30 days, same project/host/version/scope/skill version. These are conservative learning defaults, not qualification. Quality failures and repair burden precede attributable whole-task cost/allowance, otherwise elapsed time is a labeled proxy. Estimates, tokens and rounded account-limit deltas are not subscription spending. Missing or incompatible evidence yields baseline; incomplete cross-session comparisons are excluded while full lineage remains recorded.

## Capture relevant checks once

For evidence that can support learning, run the actual authorized check through `capture` with `cwd`, `host`, `run_id`, and `command` (an executable/argument array, no shell interpolation). Optional `timeout_ms` defaults to 30000, capped at 120000. This executes the check once, writes its request/exit/output under the external local state directory's project/host `evidence` folder, and returns an exact `reference` for the receipt. It is a capture wrapper for checks already needed, not an extra model call or a request to repeat completed checks. Do not put secrets in command arguments or outputs. Run ordinary checks directly if the helper is unavailable.

Use that reference in the corresponding check's evidence. A successful exit still requires the coordinator to inspect whether the check actually establishes the requested behavior. Plain files containing self-written success claims cannot establish positive learning. Existing externally captured artifacts can still be recorded, but without helper-captured check provenance this version conservatively leaves them unverified for adaptation. Incomplete/failed comparable history causes baseline fallback rather than disappearing from comparisons.

## Record all work

Call `record` with `cwd`, `host`, `run_id`, `mode` (`direct` or `delegated`), `acceptance` (`accepted`, `failed`, `blocked`, `rejected`), `relevant_checks_complete`, `attempts`, `checks`, and `usage` (null if unknown). Delegated records additionally require `pack_path` and `stratum_digest`. The helper binds the actual pack and installed folder, stamps completion time, validates and exports a canonical `delegate_receipt.v2`; report its returned `receipt_path`. Do not invent a separate receipt shape. If recording fails, preserve available attempt/check artifacts and state the gap.

Each attempt includes these exact fields:

```json
{"attempt_id":"coordinator-1","role":"coordinator","candidate_id":null,"candidate_identity":null,"evidence_tier":null,"configured":{"model":null,"effort":null},"observed":{"model":null,"effort":null},"outcome":"accepted","started_at":null,"completed_at":null,"evidence":[]}
```

Roles are `coordinator`, `worker`, `reviewer`, `repair`. Use actual pack IDs/identities and `qualified` or `provisional` tier for routed work. Include coordinator effort, every failed launch, fallback, repair and reviewer; when the coordinator reviews, retain its coordinator attempt and add the review check rather than invent a second execution. Keep configured and observed settings separate, null when unknown. Evidence consists of `{ "path": "/absolute/artifact", "digest": "sha256:<hash-of-file-bytes>" }` references to captured requests, traces or checks. Preserve source files so future advice can revalidate them.

Each check is `{ "name": "descriptive check", "kind": "test", "outcome": "passed", "evidence": [] }`. Kinds: `test`, `artifact`, `source`, `visual`, `review`, `calculation`; outcomes: `passed`, `failed`, `unverified`. Supply independently captured evidence, not merely a written assertion of success. Relevant checks must be complete; delegated work needs a review check and live research needs source checks. Missing references, failed acceptance checks, or identity contradictions cannot support positive learning. Keep relevant visual checks and required independent review.

Optional usage is `{ "metric": "attributable_cost", "unit": "USD", "value": 0, "source": {"path":"/absolute/measurement","digest":"sha256:<hash>"}, "complete": true }`. Other metrics: `allowance`, `api_equivalent`, `tokens`. Use complete=true only when all coordinator/worker/review/failure/repair work is included. No observation means null, never zero.

`correct`: supply `cwd`, `host`, stable `event_id`, `run_id`, short `reason`, optional evidence references. Corrections append without rewriting originals; a missing match stays unassigned. `status` reports counts/settings. `disable` accepts `target` (`learning` or `reminders`) and `enabled` (default false; true re-enables); for an explicit frequency preference, the reminders target also accepts a positive `max_per_session` (default 1). Repeated identical milestones and explicit dismissals remain suppressed. `reset` clears this project's host-specific learning, owned check captures and exported receipts only when requested. Never reset to improve apparent performance.

## Session reminders

At a meaningful milestone call `advise` with `cwd`, `host`, `run_id` and `reminder`. Required booleans are `safe_boundary`, `remaining_work`, `active_workers`, `coupled_investigation`, `rediscovery_required`, `completed_context_dominates`, and `next_phase_independent`. Describe observed conditions honestly. Include a `handoff` with `objective`, `constraints` (list), `decisions` (list), `checkout_state`, `completed_checks` (list), `evidence_locations` (list), `next_action`, and `unresolved_risks` (list).

If the host exposes a reliable signal, include `signal: {kind: "host_pressure" | "compaction", observed_at: <ISO timestamp>, source: <host event reference>}`. Optional `context_used_tokens` and `context_window_tokens` carry timestamped host measurements; they do not themselves trigger a threshold reminder. No new telemetry collector is required. Current context occupancy, cumulative usage, and subscription cost are different; no universal token/message/image/session-age thresholds apply. Without telemetry, a safe milestone plus completed-context dominance and an independent next phase permits advice labeled qualitative judgment. A host signal alone never establishes savings or a need to restart.

If `suggest` is true, briefly explain why this boundary helps and include the returned compact handoff. Do not automatically stop work, create/fork a task, compact, or restart. Default to once per session. An explicit accepted/dismissed/continued reply can be recorded with `reminder: {response: "accepted" | "dismissed" | "continued"}`; never infer acceptance from silence. Continuing work is allowed; do not repeat the reminder. Honor requests to disable or re-enable reminders locally. A full-history fork is not a compact handoff.
