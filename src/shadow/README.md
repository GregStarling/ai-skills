# Bounded shadow replay

Create one `createShadowSession(policy, runId)` per run, then call `executeShadow` with a governed incumbent delegation input and an isolated challenger evaluation input. Policy must explicitly enable shadow execution and declare its task limit and sampling fraction. Sampling hashes task/cohort identity before outcomes are known. A session cannot select a task twice or exceed its task budget; the budget applies to that in-process run, not a distributed quota.

Both lanes share preflight, matching, budget, preservation and cleanup code. Preflight checks exact task/order, cohort, constraints, initial file inventories, independent workspace roots and current incumbent authority. It refuses symlinks, broad directory scopes, high/critical protected risks and unsupported capabilities. `safe: true` cannot override these checks.

The demonstrable safe subset allows existing local-file edits with `readOnlyFileCheck` assertions. This trusted checker hashes a confined file without running candidate source. Arbitrary shell commands, `node -e`, repository test scripts and network-capable checks are refused. The native route calls governed `executeDelegate` for the incumbent and `executeEvaluation` for the challenger, uses the same fixture grader, preserves the incumbent output and discards the challenger workspace. A challenger failure does not replace the incumbent. Unknown costs stay unknown and cannot support cost comparisons.

Current harvested Vitest graders execute candidate source without an enforced grader sandbox, so automatic production shadow returns `native_shadow_grader_sandbox_unavailable` before dispatch. A future read-only fixture harness is admitted only when its entire grader matches `readOnlyGraderSource`; declaring a harness name or safe capability does not authorize arbitrary code. Current unknown production runtime controls also remain qualification blockers.

`simulateShadow` exercises two actual local subprocesses through `simulateDelegate`, with the same safety/matching/cleanup core. Its worker commands are trusted synthetic algorithm-test inputs, not sandboxed native candidates. Reports remain explicitly simulation, retain unknown costs and cannot be used as production authority or performance evidence. The incumbent workspace remains available; a selected challenger's workspace is discarded even when it fails.
